# Еталонні джерела Erlang/OTP

Clause відстежує офіційну гілку `maint-29`. Перевірена прив'язка (pin)
зберігається в [`references/otp-pin.cmake`](../references/otp-pin.cmake):

- Ревізія `9710673e5916164dff9616327df7de39f1aa75a9` (OTP 29.1.2, коміт
  upstream від 2026-10-22), оновлена 2026-10-24.
- Встановлений оракул для еталонів і аудитів: OTP 29.1.1 / ERTS 17.1.

`references/otp` — ігнорований checkout. Звичайні збирання й тести
використовують еталони, що належать проєкту, і не потребують ні checkout, ні
встановленого OTP. Конфігурація й тести ніколи не завантажують і не просувають
еталонну ревізію. Живі аудити вмикаються явно через `-DCLAUSE_OTP_AUDITS=ON`;
див. [повторне генерування фікстур](../tests/fixtures/patternmatch/generated/README.md).

Вихідний код OTP, скопійовані допоміжні файли й заголовки, згенеровані OTP,
ніколи не потрапляють у Git. Закомічені тестові вхідні дані написані локально;
закомічені еталони є спостереженнями за цими вхідними даними. Див.
[валідацію](validation.md#fixtures-and-provenance).

## Процедура оновлення

Виконується на початку роботи, що залежить від OTP.

1. Перевірте `git -C references/otp status --short` і збережіть локальну роботу.
   Завантажте:
   `git -C references/otp fetch https://github.com/erlang/otp.git refs/heads/maint-29:refs/remotes/origin/maint-29`.
   Перегляньте `git -C references/otp log -1 origin/maint-29` і зміни з моменту
   прив'язки, особливо граматику, сканер, препроцесор і вхідні дані корпусу.
2. Перемотайте вперед чисту локальну гілку: `git merge --ff-only origin/maint-29`
   (перше налаштування: `git switch --create maint-29 --track origin/maint-29`).
   Використовуйте байти checkout з LF (`core.autocrlf=false`), щоб контрольні
   суми збігалися на кожному хості; в наявному checkout у Windows нормалізуйте
   лише текстові файли з маніфесту та `erl_parse.yrl`, а бінарні фікстури
   upstream залишайте без змін.
3. Згенеруйте заголовок компілятора з тієї самої ревізії (з кореня проєкту):
   `perl references/otp/erts/emulator/utils/beam_makeops -compiler -outdir references/otp/lib/compiler/src references/otp/lib/compiler/src/genop.tab`.
   У Windows нормалізуйте до LF лише згенерований `beam_opcodes.hrl`.
4. Оновіть прив'язку й перевірте кожен шлях у
   `tests/fixtures/parser/phase6/otp.tsv`. Оновлюйте хеші лише після перегляду
   реальних змін upstream. Якщо змінюється `erl_parse.yrl`, перегляньте
   `tests/fixtures/parser/grammar.tsv`, його фікстури та `phase6/coverage.tsv`;
   кожне звичайне правило виведення потребує виміряного свідка.
5. Сконфігуруйте з `CLAUSE_OTP_AUDITS=ON` і `CLAUSE_OTP_SOURCE_ROOT`, що вказує
   на checkout. Запустіть тести аудиту та
   `tests/compiler/patternmatch/regenerate.py --corpus all --check`. Запишіть
   ревізію та результати нижче; повідомляйте про розбіжності, а не генеруйте
   повторно, щоб їх приховати.
